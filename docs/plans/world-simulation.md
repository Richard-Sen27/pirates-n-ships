## What exists and what is missing

Exists: port registry (`…/world/port/PortRegistry|PortIndex|Port|Berth`, saved data, nearest/containing lookups); markets (`…/trade/market/Market` price = base × role × e^(k·imbalance); `TradeService.buy/sell`, `TradeData`, `PortProfile.goodsWith(PRODUCES|DEMANDS)`); template placement (`…/ship/template/ShipTemplatePlacer.place(level, id, feet, facing, force, assemble, player)` — 4 cardinal facings only; `placeAtBerth`); `ShipBody.setOrientation/placeAt`, `SableShips.remove(ship)` (REMOVED → registry/runtime/station cleanup already wired in `AssemblyModule`, `Stations`, `SailingRuntimes`, `JobBoard`); crew (`StationContent.CREW_MEMBER`, `CrewStations.assign/order/orderShip`, `JobBoard.post`, `SailOrder.HOIST`); mobs with faction hostility (`SeafarerMob.setStationary`, `HostilityRules`, `MobCommands.spawn`); flags (`FlagpoleBlockEntity.commandSet(kind, struck, actor)`, `ShipData.flag`); navy observers (`FlagCrimes.observe` finds navy entities within `observe_range` of a ship → `seen_under_jolly_roger` already fires for any navy mob, including one on a patrol ship); bounties (`LawService.hasBounty/wantedLevel`); cannon crews (`CannonStation.CannonOrder.FIRE|LOAD`, auto-reload, `CannonService.aim/fire`, `CannonShipHits.register`); chart cells (`ChartSampler` — loaded chunks only); `WorldSimConfig` (section `world_simulation`, values listed in §17), `KrakenSpawner` (per-check chance pattern), `ShipDayTick` (dawn pattern).

Missing (each assigned below): an NPC helmsman / hold-course helm station (`HelmBlock` is not a `StationBlock`; grep for hold-course finds nothing) → WS3a; NPC cannon targeting (FL2 notes "no autonomous targeting") → WS4a; a "ship sunk" or "ship captured" event (flooded ships just sink physically; §8.4 capture is unimplemented) → WS3b; a public rudder setter that works in both steering modes (`ShipControls.setWheel` only feeds drag steering; click mode reads the `HelmBlock.RUDDER` state) → WS3a; port-to-port distances (`HarborDeskService.destinations` uses `DEFAULT_DISTANCE`) → WS2; chunk tickets (none used; vanilla `ServerChunkCache.addRegionTicket` + `TicketType.create` is loader-free) → WS3b; `Deeds` (REP1, in progress, no files on main yet) → WS1 listens when merged.

Module rule: one `ModModule` per package under `…/worldsim/<sub>/` (ids `worldsim.faction`, …), one line each in `core/ModModules` (orchestrator). `WorldSimConfig` must gain a `public static ConfigSection sub(String name, String comment)` (one line; do it before wave 1) so packages add `world_simulation.<sub>.*` from their own config classes without editing the shared file.

## Packages

### WS1 — Faction state
**Goal.** Saved per-world state for Navy, Pirates, Merchants: aggression and wealth per faction, tension per pair; shifted by deeds and world events, decaying daily; readable by all later packages; `/pirates world factions`.

**Decisions.** (1) Values in 0..1 (aggression, tension) and wealth as a long; a pure `FactionRules.apply(state, FactionEvent, strength)` with a fixed event→delta table in code and one config scale per event class (not a config per deed: §17 only needs strengths). (2) Deeds feed through a `Deeds.onRecorded` listener (REP1's registry) mapped in `FactionDeeds` (deed → `FactionEvent`); if REP1 is not merged when WS1 starts, WS1 ships `FactionEvents.report(server, event)` and the orchestrator adds the 10-line `FactionDeeds` after REP1. (3) Decay on the overworld day change (same edge as `ShipDayTick`), toward aggression 0.3 / tension 0.

**Files (common).** `…/worldsim/faction/FactionState` (record + codec), `FactionRules` (pure), `FactionEvent` (enum: PIRATE_KILLED_BY_NAVY, NAVY_KILLED_BY_PIRATE, MERCHANT_PLUNDERED, CONVOY_DELIVERED, CONVOY_SUNK, RAID_SUCCEEDED/REPELLED, PATROL_LOST, …), `FactionData` (SavedData `pirates_n_ships_factions`, pattern `…/world/port/PortRegistry`), `Factions` (service), `FactionDeeds`, `FactionCommands`, `FactionConfig`, `FactionModule`, `FactionGameTests`; JUnit `FactionRulesTest`.

**API.** `Factions.state(server)`, `Factions.aggression(server, Faction)`, `Factions.tension(server, a, b)`, `Factions.wealth(server, f)`, `Factions.report(server, FactionEvent)`; uses `…/law/flag/Faction`.

**Config** `world_simulation.factions.*`: `enabled`, `decay_per_day` 0.05, `event_scale` 1.0, `deed_scale` 1.0, `max_wealth`.

**GameTests.** Report PIRATE_KILLED_BY_NAVY twice → tension(Navy,Pirates) rises, never above 1; CONVOY_DELIVERED raises Merchants' wealth; a simulated day edge decays by `decay_per_day` (own batch with `ConfigOverrides`); `enabled=false` ignores events; command prints three lines; round-trip JUnit codec test; `Deeds.record(player, PLUNDER_MERCHANT)` shifts tension (only if REP1 is present).

**Risks.** REP1 merge order; double counting when both a deed and a world event describe the same act (rule: world events for NPC-side outcomes, deeds for player acts).
**Open.** Should villages count as Merchants or as navy-aligned (affects WS5 targets)?

### WS2 — Sea lanes, voyage records, scheduler, convoy economics
**Goal.** Compute cached sea routes between ports, keep abstract voyages as saved records that advance on the server tick, spawn merchant convoys from the ports' produce/demand at config frequencies, and settle arrivals on the markets. No ship is placed.

**Decisions.** (1) **Sea grid from the biome source, not chunks**: `SeaGrid.isSea(cx, cz)` = the noise biome at the cell centre (`generator.getBiomeSource().getNoiseBiome(..., randomState.sampler())`, as `PortService.portOf` does) is in `#minecraft:is_ocean` or `#is_deep_ocean` (rivers excluded); cell 32 blocks (`lanes.cell_blocks`); no chunk is ever loaded. Reason: lanes must cross unexplored sea; heightmap/chart cells only exist in loaded chunks. (2) A* with 8 neighbours, a land margin of 1 cell (cells touching non-sea cost ×4, so lanes keep off coasts), budget `lanes.max_cells` 20 000; endpoint = nearest sea cell within 8 cells of the port's first berth (else the centre); result simplified to waypoints (collinear runs merged) and cached per unordered pair in `LaneData` (SavedData `pirates_n_ships_lanes`, with `lanes.version`); failure cached for a day. Straight-line fallback only when A* finds no path (flagged `coastal=false`). (3) Voyage record: `Voyage(id, kind CONVOY|PATROL|RAID, faction, template, from, to, waypoints, legIndex, progress, cargo Map<good,int>, crew, fighters, health 0..1, state SAILING|MATERIALISED|ENDED, departedTick, shipId?, pursuit?)` in `VoyageData` (`pirates_n_ships_voyages`). (4) Scheduler every `tick_interval` (20) on `SERVER_TICK_END`: advance `speed_blocks_per_second` × wind factor (`WindService.sample` at the position; downwind 1.2, headwind 0.6, toggle `wind_affects_speed`); spawn rolls `convoys_per_day / checksPerDay`, capped by `max_simultaneous_voyages`; origin weighted by number of PRODUCES goods, destination = a port that DEMANDS one of them, weight 1/distance; cargo 1–3 goods × `convoy_cargo_units` (64); departure = `Market.buy` at origin, arrival = `Market.sell` at destination through a new `TradeService.npcTrade(server, port, good, side, qty)` (no plunder verdict, no coins). (5) Templates per faction from config string lists (`merchant_templates`, `navy_templates`, `pirate_templates`, default both sloops) — no `ShipTemplate` schema change. (6) Also replace `HarborDeskService.DEFAULT_DISTANCE/RISK` with lane length and a risk from the pirate islands within `risk_radius` of the lane (small, optional follow-up inside WS2).

**Files.** `…/worldsim/lane/SeaGrid` (interface + `BiomeSeaGrid` + `SeaGrid.allSea()` for tests), `LanePathfinder` (pure A*), `Lane` (record), `LaneData`, `Lanes` (service); `…/worldsim/voyage/Voyage`, `VoyageKind`, `VoyageData`, `VoyageRules` (pure: advance, pick origin/destination/cargo, spawn chance), `VoyageEconomy`, `VoyageScheduler`, `VoyageCommands` (`/pirates world voyages [list|spawn convoy <from> <to>|advance <id> <blocks>|lane <from> <to>]`), `VoyageConfig`, `VoyageModule`, `VoyageGameTests`; JUnit `LanePathfinderTest`, `VoyageRulesTest`; change `…/trade/TradeService` (npcTrade), `…/trade/desk/HarborDeskService` (distances).

**API.** `Lanes.between(server, portA, portB)` → `Optional<Lane>` (waypoints, length); `Lanes.positionAlong(lane, progress)`; `Voyages.active(server)`, `Voyages.spawnConvoy(server, from, to, rng)`, `Voyages.end(server, id, VoyageEnd reason)`, `Voyages.onSpawn/onEnd(listener)`, `Voyage.position()`; `VoyageScheduler.check(server, now, rng)` (test entry point).

**Config** `world_simulation.lanes.*` (`cell_blocks` 32, `land_margin_cost` 4, `max_cells`, `version`), `world_simulation.voyages.*` (`tick_interval_ticks` 20, `speed_blocks_per_second` 4, `wind_affects_speed`, `convoy_cargo_units` 64, template lists, `convoy_min_distance` 200); existing `convoys_per_day`, `max_simultaneous_voyages`.

**GameTests.** Two fake ports (`PortRegistry.add` with `gametest/` ids, removed at the end, pattern `…/ship/template/ShipOrderGameTests`) on `SeaGrid.allSea()`: a convoy spawned by `spawnConvoy` advances by speed × ticks and ends at the destination with the destination's price of its good lower and the origin's higher (compare `Market.midPrice` before/after); a grid with a land bar between the ports makes the lane bend around it (JUnit) and a sealed-off port yields empty; `convoys_per_day=0` spawns nothing in 600 ticks; cap respected; records survive `VoyageData` encode/decode (JUnit); `enabled=false` freezes progress.

**Risks.** Biome-noise sampling cost on first pathfinding (cache; compute lazily off the hot path, one lane per check); ports in fjords whose berths lie in beach/river biome cells (endpoint search radius); vanilla ocean biomes can hold small land (WS3b verifies water at placement). **Open.** Default speed; whether contracts should show the lane distance.

### WS3a — NPC helmsman: hold-course helm station
**Goal.** A crew member at the helm holds a course toward a point or along waypoints using the rudder; the station other packages drive NPC ships with.

**Decisions.** (1) `HelmBlock implements StationBlock` (kind `HelmStation`, seat beside the wheel via `StationSpot`); `ship/hull/pump/BilgePumpBlock` already shows `ship` implementing `station`. (2) Order `CourseOrder(List<Vec3> waypoints, boolean loop)` implementing `CrewOrder` (id `hold_course`; a record, not an enum — `StationKind<O>` is generic; `CrewOrder.ids()` lists only the id). (3) Continuous operation: `HelmStation.durationTicks` returns the ticks to the last waypoint estimate, and a `LEVEL_TICK_END` loop runs the pure `CourseKeeper.rudder(heading, bearing, yawRate, maxRudder, params)` (P-control on heading error with deadband `deadband_degrees` 3, anticipation from yaw rate) every 5 ticks; `headingDegrees` from `SailingRuntime.headingDegrees(ship)`. (4) New `ShipControls.setRudderAngle(level, helmPlotPos, degrees)` writes both the wheel (`setWheel`) and the block-state step, so it works whatever `helm.wheel.drag_steering` is; refused while `HelmService.session` has a player at that helm ("Someone else is at the wheel"). (5) Arrival within `arrival_radius` (8) advances the waypoint; at the last one the helmsman centres the rudder and reports; stuck detection (`stuck_ticks` 200 under 0.3 m/s with sails set) raises a `CourseEvent.STUCK` listeners can act on (WS3b). Sails are not this station's job: callers post `SailOrder.HOIST` through `JobBoard.post`.

**Files.** `…/station/helm/HelmStation`, `CourseOrder`, `CourseKeeper` (pure), `HelmCourses` (per-ship course state, listeners), `HelmStationGameTests`; change `…/ship/assembly/HelmBlock` (implements `StationBlock`), `…/sailing/ship/ShipControls` (setRudderAngle), `…/station/StationCommands` (`/pirates crew order course <x> <z> [<x> <z> …]`); JUnit `CourseKeeperTest`. No whistle entry (avoids a conflict with WS4a in `WhistleOrders`; add later).

**API.** `HelmCourses.set(level, ship, CourseOrder)`, `HelmCourses.clear(level, ship)`, `HelmCourses.onEvent(listener)` (ARRIVED, STUCK, NO_HELMSMAN), `CourseKeeper.rudder(...)`.

**Config** `crew_stations.course.*`: `enabled`, `deadband_degrees` 3, `gain` 2.0, `arrival_radius` 8, `stuck_ticks` 200, `update_interval_ticks` 5.

**GameTests** (basin `EMPTY_40`, `SailingGameTestsShips.squareHull/openSky/assemble`, fixed wind astern): helmsman ordered to a point 20 blocks ahead and 12 to starboard: heading error < 15° within 200 ticks and ARRIVED within 400; a point astern makes the ship turn through > 120°; a player helm session blocks NPC rudder changes; releasing the crew centres the rudder; the same test with `drag_steering=false` (own config batch).

**Risks.** Sloop turning circle vs. 40-block basins (use a tender hull and modest targets); rudder authority at low speed (tests start with sails full). **Open.** Should a player be able to give "hold course" via the whistle in this package?

### WS3b — Materialisation
**Goal.** A SAILING voyage near a player becomes a real template ship on its lane heading with crew and fighters, sails along the waypoints, and turns back into a record when nobody is near; sinking, capture and plunder end or change the record, record deeds and faction events and affect prices.

**Decisions.** (1) Trigger: each scheduler check, the nearest voyage to any player within `materialize_radius` and `max_materialized` (4) not reached; the spawn column must be loaded (`level.isLoaded`) or a region ticket (`TicketType.create("pirates_n_ships:voyage", …)`, radius 2, `ticket_ticks` 600) is taken and the voyage retried next check; surface water verified (`HazardSpawner.WORLD.openWater`-style check). (2) Placement: `ShipTemplatePlacer.place` with `facing` = cardinal nearest the leg heading, `feet` 3 blocks behind the point, `force=false`, `assemble=true`, `player=null` → then `ShipBody.setOrientation` to the exact heading, `ShipAssembler.name`, flag through the first `FlagpoleBlockEntity.commandSet` (merchant/navy/jolly roger), cargo into `CargoContainerBlockEntity.insertAll`, `CrewMember`s seated by `JobBoard.post(SailOrder.HOIST)` plus one assigned to the helm with `CourseOrder(remaining waypoints)`; fighters (`Pirate` / `NavySoldier`+`NavyOfficer` / `Sailor`) on deck spots (`DeckSpots`: top template block per column above the waterline with 2 air above) with `setStationary(true)`, `setPersistenceRequired`. Voyage↔ship link in the record (`shipId`) and the sub-level user data `pirates_n_ships_voyage` (pattern `SailingRuntimes.USER_DATA_KEY`) for recovery after a reload. (3) Dematerialise after `linger_ticks` (200) with no player within `materialize_radius + 64`: progress = lane projection of the ship's centre; health = 1 − flooded fraction (`HullRuntime.lastReport().floodVolume` / basin volume); cargo = container sums; entities with the voyage mark discarded; `SableShips.remove`. (4) Endings (`VoyageEnd`): SUNK when the flooded fraction ≥ `sunk_flood_fraction` 0.8 or `ShipSplits.isWreck` or the bounds top is under the sea for 100 ticks → deed `SINK_MERCHANT|NAVY|PIRATE` for the last player shooter (`CannonShipHits.register`, 1200-tick memory), faction event, cargo lost; CAPTURED when all fighters are dead and a player stands aboard (`ShipEntities.standingOrRiding`) for `capture_hold_ticks` 100 → `ShipData.withOwner(player)`, crew released, voyage ended, deed `CAPTURE_*`; PLUNDERED when cargo units drop while a player is aboard → deed `PLUNDER_MERCHANT` once per voyage, `PlunderMark` on the goods taken is left to the existing plunder rules (check `…/trade/plunder/PlunderMark` application), record cargo reduced, voyage continues. STUCK (from WS3a) → dematerialise and skip to the next waypoint.

**Files.** `…/worldsim/materialize/Materializer`, `DeckSpots` (pure), `VoyageShips` (voyage↔ship map, marks), `VoyageCrew` (spawn/discard), `VoyageEndings` (pure rules + service), `VoyageChunks` (tickets), `MaterializeConfig`, `MaterializeModule`, `MaterializeGameTests`; JUnit `DeckSpotsTest`, `VoyageEndingsTest`.

**API.** `Materializer.materialize(server, voyageId)` / `dematerialize(server, voyageId)` (test and command entry), `VoyageShips.voyageOf(shipId)`, `Voyages.onEnd` already from WS2.

**Config** `world_simulation.materialize.*`: `max_materialized` 4, `linger_ticks` 200, `ticket_ticks` 600, `sunk_flood_fraction` 0.8, `capture_hold_ticks` 100, `crew_per_ship` 3, `fighters_merchant` 2 / `fighters_navy` 4 / `fighters_pirate` 4; existing `materialize_radius`.

**GameTests** (`EMPTY_48` basins, templates placed with `force=false`): materialize a convoy → a ship exists at the lane point within 2 blocks, heading within 10° of the leg, Jolly Roger/merchant flag read by `ShipAllegiance`, cargo count equals the record, crew count and fighter count as configured; dematerialize → ship gone, record SAILING with progress advanced by the distance the ship moved and the cargo preserved; flooding the hull past the fraction ends the record SUNK and a mock-player shooter's deed is recorded (REP1 present) or the faction event fires; killing all fighters with a mock player aboard transfers ownership; removing 10 units from a crate records PLUNDERED; `max_materialized` cap; reload safety is a JUnit codec test.

**Risks.** The 2048 block limit and obstruction at sea (kelp, icebergs: verify `ShipBlockRule.isFreeForShip` on water plants); chunk tickets keeping too much loaded; Sable unloading a ship whose chunk unloads before we dematerialise (then `UNLOADED` fires: keep the record MATERIALISED and re-adopt by user data on load); crew strolling off deck (crew are seated; fighters stationary). **Open.** Default `materialize_radius` 192 exceeds many servers' view distance (160): clamp to `(viewDistance − 1) × 16`?

### WS4a — NPC gunnery
**Goal.** Gun crews fire at a chosen or any hostile ship within their arc and range, reusing the existing cannon stations, loading and auto-reload.

**Decisions.** (1) Pure `GunCrewAim`: a gun's world barrel axis (`CannonService.barrel` through the ship orientation), target bounds centre, `CannonConfig` muzzle speed and gravity → in-arc (±`arc_degrees` 15 horizontal), in-range, and the elevation step with the smallest miss from the ballistic table; `CannonService.aim(level, pos, up)` steps toward it (one step per `aim_interval_ticks`), then `CannonOrder.FIRE` is posted to the manned, loaded gun. (2) `CannonOrder.FIRE_AT_WILL` (new enum value, whistle entry "Fire at will", `/pirates crew order fire_at_will`): per-ship `GunneryState` (AT_WILL | target UUID | off) in `Gunnery`; targets are ships within `engage_range` (64) that `ShipHostility.hostile(selfFaction, targetFlagReading, targetOwnerWanted, targetStance)` says are hostile (pure; Navy: Jolly Roger, unmasked, or owner wanted/bountied; Pirates: navy flag or merchant; Merchants: Jolly Roger only; SURRENDERED never). For a player's ship `selfFaction` is from its flag. (3) Crew shots keep "no owner" (G9) so no crimes attach to NPC fire.

**Files.** `…/combat/cannon/npc/GunCrewAim` (pure), `ShipHostility` (pure), `Gunnery` (service + level tick), `GunneryConfig` (`cannons.npc.*`), `GunneryGameTests`; change `CannonStation.CannonOrder` (FIRE_AT_WILL), `…/station/order/WhistleOrders` (entry), `StationCommands`; JUnit `GunCrewAimTest`, `ShipHostilityTest`.

**Config** `cannons.npc.*`: `enabled`, `arc_degrees` 15, `engage_range` 64, `aim_interval_ticks` 20, `fire_interval_ticks` 40, `npc_block_damage_multiplier` 0.5.

**GameTests.** Two assembled hulls 24 blocks apart, the gunner's cannon loaded and crewed: AT_WILL against a Jolly Roger target fires within 100 ticks and `CannonShipHits` reports a hit on the target; a target abeam of a bow-facing gun (outside the arc) gets no shot; a struck-colours target gets no shot; `enabled=false` fires nothing; a raised target makes the gun step its elevation.

**Risks.** Hit rate on moving targets (lead the target by its velocity, `ShipBody.linearVelocity`); block damage to player ships (multiplier). **Open.** Should AT_WILL also be the default for a player's crew after "Fire!"?

### WS4b — Navy patrols and hunting
**Goal.** PATROL voyages between navy outposts, which divert to hunt Jolly Roger ships or bountied captains near players, engage with WS4a, and break off on surrender; frequency and reach scale with navy aggression and Navy–Pirates tension.

**Decisions.** PATROL kind in WS2's scheduler: `patrols_per_day × (0.5 + aggression)`; outpost→another outpost, else out `patrol_radius` along the lane toward the nearest pirate island and back. Hunting: `HuntRules.pick(patrolPos, candidateShips)` (pure) selects a player ship within `hunt_radius` (256) flying the Jolly Roger (`ShipData.flag`) or whose owner has a bounty ≥ `hunt_bounty_minimum` or wanted ≥ `law.world.navy_hostility_threshold`; the record gets `pursuit = shipId`, moves straight toward the target abstractly (no lane), materialises as usual; materialised: `HelmCourses.set` to the target's position every 40 ticks (hold `standoff_distance` 20), `Gunnery.set(target)`; give up after `give_up_ticks` without closing or when the target is out of range; on `FlagReading.isStruck` cease fire and shadow for `surrender_linger_ticks`, then resume (boarding is out of scope). Each patrol kill of a pirate mob reports `PIRATE_KILLED_BY_NAVY`; a sunk patrol reports `PATROL_LOST`.

**Files.** `…/worldsim/navy/PatrolPlanner`, `HuntRules` (pure), `Hunting` (service), `NavyConfig`, `NavyModule`, `NavyGameTests`; small changes in `VoyageScheduler` (kind dispatch hook `VoyagePlanner` interface registered by kind).

**Config** `world_simulation.navy.*`: `hunt_radius` 256, `hunt_bounty_minimum` 50, `give_up_ticks` 2400, `standoff_distance` 20, `patrol_radius` 400, `surrender_linger_ticks` 600; existing `patrols_per_day`.

**GameTests.** A registered Jolly Roger player ship 100 blocks from an abstract patrol → the record switches to pursuit within one check; a clean merchant-flag ship is ignored; a bountied owner is hunted; materialised patrol in a basin with a Jolly Roger hull in arc fires (WS4a); striking the colours stops the fire within `fire_interval_ticks`; aggression 0 vs 1 changes the spawn chance (JUnit on `PatrolPlanner`).

**Risks.** Chasing through land (pursuit ignores lanes; cap pursuit to open-sea cells by `SeaGrid`); patrols near outposts with the garrison already shooting. **Open.** Should patrols board a surrendered player (needs boarding AI, later)?

### WS5 — Raids and retaliation
**Goal.** The raid chance rises while a player stays at a navy settlement, capped with a long cooldown; a raid is announced (chat line, the bells of the settlement), pirate ships arrive, land fighters, and withdraw; tension between Navy and Pirates scales raids both ways.

**Decisions.** `RaidTracker` per port: minutes of presence of any player inside the port box (outposts always; villages when `raids.target_villages`) accumulate `chance = min(cap, growth × minutes)`; one roll per minute; `last_raid_day` per port in `RaidData` (cooldown `cooldown_days`); growth × `(1 + retaliation_factor × tension(Navy,Pirates))` when `retaliation_enabled`. A raid = `raids.ships` (1–2) RAID voyages from the nearest pirate island's lane endpoint, spawned `approach_distance` (320) out on the lane toward the port and materialised at once if a player is within reach (the player is at the port), with `Gunnery` AT_WILL and course to the port's berth approach point; announcement at spawn: translatable chat/title to players in the box ("Sails on the horizon!") and every vanilla `BellBlock` and `ShipsBellBlock` in the port box rung every 100 ticks for `bell_ticks` 600. Landing: within `landing_distance` (24) the helmsman centres the rudder, `ShipControls.useCapstan` drops the anchor, fighters are moved to the shore cell nearest the port's `shore_anchor`/berths with `stationary=false` and target the garrison and players (existing `factions_fight`); after `raid_duration_ticks` or when all raiders are dead the survivors are discarded and the ships leave (voyage home) → `RAID_SUCCEEDED` (a raider reached the desk) / `RAID_REPELLED`; players who kill raiders get deed `DEFEND_SETTLEMENT` (LIVING_DEATH with the raid mark). Navy retaliation on pirate islands = a PATROL whose destination is the island's approach point (reuses WS4b; it fires on pirate ships it meets) when tension is high.

**Files.** `…/worldsim/raid/RaidRules` (pure chance/cooldown), `RaidTracker`, `RaidData` (SavedData), `RaidAnnouncer`, `RaidLanding`, `RaidPlanner` (VoyagePlanner for RAID), `RaidCommands` (`/pirates world raid <port>`, `chance`), `RaidConfig`, `RaidModule`, `RaidGameTests`; JUnit `RaidRulesTest`.

**Config** `world_simulation.raids.*` (existing `chance_growth_per_minute`, `chance_cap`, `cooldown_days`) plus `ships` 1, `approach_distance` 320, `landing_distance` 24, `bell_ticks` 600, `raid_duration_ticks` 6000, `target_villages` true, `retaliation_factor` 1.0, `announce`.

**GameTests.** `RaidRules`: chance grows linearly, caps, resets after a raid, zero during cooldown, tension multiplier (JUnit); GameTest: a fake outpost port with a bell and a mock player inside for 3 simulated minutes with growth 1.0 → `/raid` forced start rings the bell (`RINGING`/`BellBlock` state) and spawns a RAID record at the approach distance; landing in a basin: a materialised raid ship within `landing_distance` of a fake port puts its pirates on the shore within 100 ticks; repelled raid reports `RAID_REPELLED` and sets the cooldown; `retaliation_enabled=false` ignores tension.

**Risks.** Landing on steep shores; raids against a village with no garrison are one-sided (villagers only); bells inside structure pieces must exist (ST4c fort gate has an alarm bell; the village may need one). **Open.** Raid villages at all? Minimum number of players present? Should raiders loot (take doubloons from the desk)?
